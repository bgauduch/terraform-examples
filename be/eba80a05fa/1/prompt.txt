## Point 1 — REVERSE_BUDGET_ACTION (APPLY_SCP_POLICY)

**Verdict: REVERSE undoes a previously executed action (detaches the SCP it attached), and it is always MANUAL/explicit. There is NO native under-threshold auto-reversal — Budgets only fires on breach; dropping back below the threshold does nothing.**

- Reverse = manual undo of a completed action:
  &gt; "Reversing a previous action … You can review and undo previously completed actions from the Action history table." — [Reviewing and approving your budget action](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-action-review.html)
  &gt; "Reversed - The action was undone, and AWS Budgets will no longer evaluate the action for the remaining budgeted period." — same page.
- CLI/API surface (manual invocation), enum confirmed:
  &gt; `--execution-type` allowed values: `APPROVE_BUDGET_ACTION | RETRY_BUDGET_ACTION | REVERSE_BUDGET_ACTION | RESET_BUDGET_ACTION` — [execute-budget-action CLI](https://docs.aws.amazon.com/cli/latest/reference/budgets/execute-budget-action.html). "Executes a budget action." (same page). You call it via console "Run action"/undo, `aws budgets execute-budget-action`, or the `ExecuteBudgetAction` API.
- No auto-undo on spend dropping: the trigger model is breach-only (actual/forecast exceeding), and reversal is a separate explicit operation. There is no "GREATER_THAN crossing back down ⇒ auto-detach" mechanism — the only automatic re-evaluation is `Reset` (manual) or the natural reset at the **start of the next budget period** for IAM/SCP action types. Note also, once **Reversed**, Budgets "will no longer evaluate the action for the remaining budgeted period" (quote above) — i.e. it won't even re-apply on a subsequent breach in the same period unless you Reset.

## Point 2 — RCP via Budget Actions

**Verdict: FALSE — no native RCP support. Budget actions attach only SCP among Organizations policy types. Full action_type enum is exactly three: APPLY_IAM_POLICY, APPLY_SCP_POLICY, RUN_SSM_DOCUMENTS. No APPLY_RCP / RCP definition exists.**

- Enum + definition types:
  &gt; `--action-type` allowed values: `APPLY_IAM_POLICY | APPLY_SCP_POLICY | RUN_SSM_DOCUMENTS`; `--definition` supports `IamActionDefinition`, `ScpActionDefinition`, `SsmActionDefinition`. "No, there is no RCP/Resource Control Policy definition." — [create-budget-action CLI](https://docs.aws.amazon.com/cli/latest/reference/budgets/create-budget-action.html)
- RCPs are a distinct Organizations authorization-policy type (resource-centric guardrail), separate from SCPs and not wired into Budgets:
  &gt; "A resource control policy is a type of policy that offers central control over the maximum available permissions for resources in an organization." — [Organizations concepts / RCP](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_getting-started_concepts.html) (detail: [RCPs](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_rcps.html))
- To attach an RCP on a budget breach you'd need a custom path: Budgets/CloudWatch billing alarm or budget notification → SNS/EventBridge → Lambda calling Organizations `AttachPolicy` with an RCP `PolicyId` (RCPs must be enabled as a policy type first). That is not a native budget action.

Both requested facts are date-stable as of today except the CLI enums, which track the current AWS Budgets API version (`budgets-2016-10-20`); a future action type (e.g. an RCP option) would appear there first.</result>
